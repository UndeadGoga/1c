# Локальный стенд отказоустойчивости 1С + PostgreSQL

Этот проект разворачивает отказоустойчивый кластер СУБД (PostgreSQL + репликация + PgPool-II) в Docker, 
а сервер 1С предлагается использовать нативный (установленный на хост-машине).

## Архитектура

```
[Клиент 1С (Ваш ПК)] 
       ⬇
[Нативный сервис 1С:Предприятие (Ваш ПК)] 
       ⬇
[HAProxy (Docker)] -> [PgPool-II (Docker)] -> [PostgreSQL Primary (Docker)]
                                           ↘ [PostgreSQL Replica (Docker)]
```

## Требования

1.  **Docker & Docker Compose**
2.  **Установленная платформа 1С:Предприятие 8.3** (Сервер 1С должен быть установлен и запущен как служба или вручную).
    *   Для Windows: "Сервер 1С:Предприятия" в службах.
    *   Для Linux: пакет `1c-enterprise-server`.
3.  **Право на создание кластера БД** (пользователь postgres).

## Быстрый старт

### 1. Развертывание СУБД и мониторинга

```bash
cd docker-compose
docker compose up -d
```

Это поднимет:
*   `pg-primary`: Основная база данных (порт 5432 внутри сети).
*   `pg-replica`: Реплика (только чтение).
*   `pgpool`: Балансировщик соединений для БД (порт 5433 наружу).
*   `haproxy`: Балансировщик для 1С (если нужно будет добавить второй сервер позже).
*   `prometheus` & `grafana`: Мониторинг.

### 2. Настройка нативного сервера 1С

Так как сервер 1С работает на вашем хосте, ему нужно разрешить подключаться к базе в Docker.

#### Для Windows:
1.  Убедитесь, что в `%PROGRAMFILES%\1cv8\conf\srvinfo.cfg` есть права на создание баз.
2.  Откройте консоль администрирования серверов 1С (`mmc` -> Добавить оснастку "Администрирование серверов 1С Предприятия").
3.  Подключитесь к локальному кластеру.
4.  Создайте новую информационную базу.
5.  Тип СУБД: **PostgreSQL**.
6.  Сервер БД: `localhost` (или IP вашего Docker хоста).
7.  Порт БД: **5433** (это порт PgPool, а не прямой порт Postgres).
8.  Имя БД: `demo_db`.
9.  Пользователь БД: `postgres`.
10. Пароль БД: `postgres123` (задан в docker-compose.yml).

#### Для Linux (Ubuntu/Debian):
Убедитесь, что сервис `postgresql` не конфликтует по портам (в нашем случае мы используем порт 5433 для Docker, так что конфликта не будет).

Создание базы через утилиту `rac` (пример):
```bash
# Создаем кластер (если еще нет)
# Создаем ИБ
rac infobase create --cluster=localhost:1545 --db-type=postgresql \
  --db-server=localhost --db-port=5433 \
  --db-name=demo_db --db-user=postgres --db-pwd=postgres123 \
  --name="Demo HA Cluster"
```
*(Замените порт кластера 1545 на актуальный, если он отличается)*

### 3. Проверка работы

1.  Запустите 1С:Предприятие (толстый или тонкий клиент).
2.  Добавьте базу в список:
    *   Тип: **На сервере 1С:Предприятия**.
    *   Кластер: `localhost:1541` (стандартный порт).
    *   Выберите созданную базу `Demo HA Cluster`.
3.  При первом запуске 1С создаст таблицы в базе данных через PgPool.

### 4. Тестирование отказоустойчивости

Теперь самое интересное. Мы можем "убить" основную базу, и PgPool должен переключиться на реплику (требуется настройка репликации, в базовой конфигурации включена потоковая репликация).

1.  Посмотрите логи PgPool: `docker logs pgpool -f`
2.  Остановите основную базу:
    ```bash
    docker stop pg-primary
    ```
3.  Попробуйте выполнить запрос в 1С или посмотреть статус в консоли администратора БД.
    *   *Примечание:* В простой конфигурации PgPool может потребовать ручного переключения (failover) или времени на осознание проблемы. Для автоматического failover в продакшене используют `watchdog` или внешние скрипты, но для теста достаточно увидеть, что реплика продолжает работать.

### 5. Мониторинг

1.  Откройте браузер: `http://localhost:3000`
2.  Логин: `admin`, Пароль: `admin`
3.  DataSource: `Prometheus` (должен подхватиться автоматически).
4.  Вы увидите метрики загрузки CPU, RAM и соединений PostgreSQL.

## Конфигурация

Файлы конфигурации находятся в папке `docker-compose`:
*   `docker-compose.yml` — основные сервисы.
*   `postgres/` — скрипты инициализации репликации.
*   `grafana/provisioning/` — настройки дашбордов.

## Остановка

```bash
docker compose down
```
*Данные баз данных сохраняются в volumes, чтобы удалить их полностью: `docker compose down -v`*
